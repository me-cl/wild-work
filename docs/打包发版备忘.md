# 打包与发版备忘

> 本文是**构建 / 打包 / 发版**的唯一操作手册：产物从哪来、版本号要改哪几处、
> 每个平台的命令与坑、CI 做了什么和**没做什么**。
>
> 相邻文档：渠道协议与凭据模型见 `渠道接入备忘.md`；决策依据与证据链见 `决议项.md`；
> 日常开发约定见仓库根的 `DEVELOPMENT.md`。

---

## 0. 产物总览

| 产物 | 产出方 | 文件名 |
|------|--------|--------|
| Windows 桌面 | **只能本地构建** | `dist/wild-work.exe` |
| Windows 桌面（CI） | GitHub Actions | `dist/wild-work-windows-amd64.exe` |
| macOS 裸二进制 | GitHub Actions（cgo） | `dist/wild-work-darwin-{arm64,amd64}` |
| macOS 安装包 | `build/macos/build-app.sh` | `dist/WildWork-<ver>-<arch>.dmg`（内层 `.app`） |
| Linux | 本地或 CI | `dist/wild-work-linux-{amd64,arm64}` |
| Android | **只能本地构建** | `shell/android/app/libs/wildwork.aar` → `*.apk` |

两条容易被忽略的事实：

1. **`dist/wild-work.exe` 只有本地能产出**。CI 的产物一律带平台后缀，从不生成这个名字
   （见 AGENTS.md §2 第 0 条不变量）。改了代码不重建，本地跑的就是旧二进制——
   典型症状是"版本号改了但界面还显示老版本"。
2. `dist/` 在 `.gitignore` 里，**不入版本控制**；它是本地产物目录，不是源码。

## 1. 版本号：真源与必须同步的位置

**唯一真源**：`internal/app/app.go`

```go
const Version = "2.11.5"
```

派生消费方（改版本号时必须逐个确认）：

| 位置 | 怎么用 | 漏改的后果 |
|------|--------|-----------|
| `build/macos/build-app.sh` | `grep` 出该常量 → Info.plist 的 `CFBundleShortVersionString`/`CFBundleVersion` + dmg 文件名 | dmg 名与 release 对不上 |
| git tag `vX.Y.Z` | CI 用它选 release note 段落、命名 release | 段落找不到 → 退化成 commit 列表 |
| `RELEASES.md` | 段落标题 `# wild-work vX.Y.Z` | 同上 |
| `shell/android/app/build.gradle` 的 `versionName` | APK 的显示版本 | 手机端显示的版本号是旧的 |
| `shell/android/app/build.gradle` 的 `versionCode` | 整数，安装器比分 | **发版必须 +1**，否则覆盖安装被系统拒绝 |

> ⚠️ 已知漂移（2026-11-05 记录）：Go 侧已是 `2.11.5`，而 `build.gradle` 的
> `versionName` 曾停留在 `2.11.4`。Android 不是 CI 产物、改版本号没有编译期校验，
> 这类漂移只能靠发版清单兜住——chore(release) 提交里请把两处一起改。

## 2. 发版前的本地校验

**CI 不做测试**。`.github/workflows/build.yml` 的全部步骤是：
`rsrc` 生成图标 → `go build` → 前端静态检查（仅 linux-amd64 一次）→
末尾换行提示（advisory，不阻断）→ macOS 打包 → 上传 artifact → 建 release。

**没有 `go test`，也没有 `go vet`。** 所以这三条必须在本地跑完再打 tag：

```bash
go build ./... && go vet ./... && go test ./...
node scripts/ui-static-check.mjs      # 前端渲染断言（仓库无 package.json，直接 node 跑）
```

改动涉及新文档时，另外自查入库状态（见 §7）。

## 3. Windows

```bash
# 1) 图标（两个文件都在 .gitignore 里，新克隆的仓库必须重跑）
go install github.com/akavel/rsrc@latest
cp build/windows/icon.ico cmd/wild-work/icon.ico
rsrc -ico cmd/wild-work/icon.ico -o cmd/wild-work/rsrc_windows_amd64.syso

# 2) 构建
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 \
  go build -ldflags "-H windowsgui" -o dist/wild-work.exe ./cmd/wild-work
```

注意点：

- **`-H windowsgui` 不能省**：省了会附带一个控制台黑框。
- **`CGO_ENABLED=0` 不能省**：纯 Go 依赖，带 cgo 会拖入 MinGW 工具链。
- 图标资源是两个**被 gitignore 的生成文件**（`cmd/wild-work/icon.ico` 与
  `rsrc_windows_amd64.syso`）。CI 在 `needs_rsrc: true` 的矩阵项里自己生成，
  本地则每次新克隆都要重跑一次；忘了跑不报错，只是 exe 没有图标。
- 构建后**核对版本号真的进二进制了**（防止拿到旧文件）：

```bash
python -c "b=open('dist/wild-work.exe','rb').read(); print('new:',b.count(b'2.11.5'),'old:',b.count(b'2.11.4'))"
# 期望 new >= 1 且 old == 0
```

用 Python 字节计数而不是 `strings`：Go 二进制的长串不一定以可打印串形式连续存在，
`strings | grep` 在这里不可靠。

## 4. Linux

```bash
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o dist/wild-work-linux ./cmd/wild-work
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -o dist/wild-work-linux-arm64 ./cmd/wild-work
```

无桌面环境（NAS / 容器 / systemd 服务）**必须带 `--no-tray`**，
否则托盘初始化会失败并直接 panic 退出（不变量 10）。

## 5. macOS

macOS 必须用**真机或 CI**（cgo 必需），不能在 Linux 上交叉编译。

```bash
CGO_ENABLED=1 GOOS=darwin GOARCH=arm64 \
  go build -trimpath -o dist/wild-work-darwin-arm64 ./cmd/wild-work

ARCH=arm64 REQUIRE_DMG=1 bash build/macos/build-app.sh
# 产出 dist/WildWork.app 与 dist/WildWork-<ver>-arm64.dmg
```

脚本参数：`ARCH`（必传，CI 的 runner 架构与目标架构未必一致）、
`BIN`（显式指定源二进制）、`REQUIRE_DMG=1`（dmg 失败即致命）。

四条硬约束（都由实测踩出来）：

1. **`Contents/MacOS/WildWork` 必须是真正的 Mach-O**。脚本直接 `cp` 二进制进去。
   不要改回"shell 启动器脚本 + exec"的老做法：那样 AppKit 建不出 `NSStatusItem`，
   表现为**守护进程正常运行、菜单栏却没有图标**。
2. **数据目录**：`cmd/wild-work` 的 `workDir()` 检测到自身位于
   `.app/Contents/MacOS` 内时，自动把 `config.json`/`auths/`/`data/` 改到
   `~/Library/Application Support/WildWork`。所以 `.app` 装进 `/Applications`
   后整体只读也没问题——**这条程序侧逻辑不能动**，改了 macOS 版就写不进数据。
3. **ad-hoc 签名是必须的**（`codesign --force --sign -`）：arm64 二进制无签名不能执行。
   但这不是 Apple 公证签名，用户首次打开仍需在 Finder 里右键 → 打开。
4. **dmg 失败默认只告警**（hdiutil 需要磁盘设备权限，沙箱环境常失败）。
   CI 传 `REQUIRE_DMG=1` 让失败变成致命，避免静默发出一个没有 dmg 的 release。

`Info.plist` 里 `LSUIElement=true`：托盘常驻程序，不在 Dock 显示图标。

## 6. Android

链路：`mobile/`（Go 导出层）→ `gomobile bind` → `wildwork.aar` → Gradle → APK。
外壳与运行行为的设计说明见 `shell/android/README.md`，这里只讲构建。

### 6.1 前置

1. **Go 1.26+**（只有这条链路需要；桌面构建仍是 1.25）
2. Android SDK + NDK
3. `gomobile`：`go install golang.org/x/mobile/cmd/gomobile@latest && gomobile init`
4. **Gradle 8.7+**（AGP 8.7.3 / Kotlin 2.0.21）+ **JDK 17**

### 6.2 生成 AAR

```bash
export ANDROID_HOME=/path/to/Android/Sdk
# ANDROID_NDK_HOME 可以不给，脚本会从 $ANDROID_HOME/ndk 里挑最新有效版本
GOPROXY=https://goproxy.cn,direct shell/android/build-aar.sh
# 产物 build/android/wildwork.aar，并自动拷到 shell/android/app/libs/
```

脚本执行 `gomobile bind -target=android/arm64,android/arm -androidapi 26
-javapkg com.wildwork`，且必须在 `mobile/` 目录下执行（它不是根模块）。

### 6.3 编 APK

```bash
cd shell/android
"$GRADLE" assembleDebug          # 仓库不带 wrapper，用本机 gradle
cp app/build/outputs/apk/debug/app-debug.apk ../../dist/wild-work-android-debug.apk
adb install -r ../../dist/wild-work-android-debug.apk
```

`local.properties`（`sdk.dir=`）由 Android Studio 或手工生成，**不入库**。

### 6.4 踩过的坑（逐条都真实发生过）

| 坑 | 说明 |
|----|------|
| **`mobile/` 是嵌套模块** | `mobile/go.mod` 是 `go 1.26.0` + `replace wild-work => ../`，根 `go.mod` 是 `go 1.25.0`。这是刻意的：x/mobile 最新版要求 1.26，加进根模块会把整个项目的语言版本抬上去，而 CI 仍是 1.25。别"顺手统一"。 |
| **仓库没有 gradle wrapper** | 没有 `gradlew`/`gradle-wrapper.jar`。用本机 gradle（8.7+），并确保 `JAVA_HOME` 指向 JDK 17。 |
| **`ANDROID_HOME` 没设** | AAR 脚本找不到 NDK 会直接失败；shell 里先 export，或写进 `local.properties`。 |
| **NDK 版本筛选** | 正确判据是"整串只由数字和点组成"（`case "$v" in *[!0-9.]*) continue ;;`）。**不要**用 `grep -v '\.'`——目录名 `27.3.13750724` 本身带点，那样筛会把所有有效版本滤掉、变量变空串、gomobile 随即失败（2026-11-05 踩到）。`.broken2`/`.partial` 目录靠非数字后缀排除。 |
| **ABI 只有 arm** | `abiFilters 'arm64-v8a', 'armeabi-v7a'`；x86 模拟器跑不起来。加 x86 只会让 APK 体积翻倍而无实际场景。 |
| **不能开混淆** | `minifyEnabled false` 必须保持：gomobile 生成的类通过 JNI 按名字绑定，混淆会把类名削掉。 |
| **版本号** | `versionName` 跟 Go 侧同步；`versionCode` 每次发版 +1。 |

### 6.5 release 签名（可选）

```bash
keytool -genkeypair -v -keystore ww.jks -keyalg RSA -keysize 2048 -validity 10000 -alias wildwork
# 在 app/build.gradle 增加 signingConfigs 指向它，然后
"$GRADLE" assembleRelease
```

`*.keystore` / `*.jks` 已在 `.gitignore` 中。

## 7. 文档入库（新增 docs 时必做）

`docs/*` 默认全部被忽略，只有显式反选（`!docs/<文件名>`）的才入库。
新增一篇需要入库的文档必须**同时**做两件事，否则他人克隆后看到的是死链：

1. `.gitignore` 追加一行 `!docs/<文件名>.md`
2. `AGENTS.md` §6 的文档索引表加一行链接

验证：

```bash
git check-ignore -v docs/<文件名>.md    # 有输出 = 仍被忽略；无输出 = 已入库
git ls-files docs/                      # 实际入库清单
```

## 8. CI 与发版流程

### 8.1 工作流

`.github/workflows/build.yml`，5 个矩阵项：

| name | runner | GOOS/GOARCH | CGO | 额外步骤 |
|------|--------|-------------|-----|----------|
| windows-amd64 | ubuntu-latest | windows/amd64 | 0 | rsrc 图标，`-H windowsgui` |
| macos-arm64 | macos-latest | darwin/arm64 | 1 | `build-app.sh`（`REQUIRE_DMG=1`） |
| macos-amd64 | macos-latest | darwin/amd64 | 1 | 同上 |
| linux-amd64 | ubuntu-latest | linux/amd64 | 0 | 前端静态检查 + 末尾换行提示 |
| linux-arm64 | ubuntu-latest | linux/arm64 | 0 | — |

几个实现细节：

- `fetch-depth: 0` 只为"末尾换行提示"那一步能拿到 `origin/master...HEAD`；
  浅克隆下该 diff 恒为空，那盏灯就永远不亮。
- 末尾换行检查是 **advisory**（`continue-on-error: true`），且只查**本次改动**的文件——
  仓库存量有 7 个文件本就没有末尾换行，全仓检查会把 5 个 job 全打挂。
- 前端静态检查只在 linux-amd64 跑一次，避免 5 个平台重复。

### 8.2 触发方式

| 触发 | 构建的代码 | 结果 |
|------|-----------|------|
| `push` tag `v*` | 该 tag | 正式 release |
| `workflow_dispatch`（手点） | 固定 `master` | `dev-build` 预发布（每次删掉重建，不堆积） |

> `workflow_dispatch` 按钮只在默认分支显示，但 `checkout` 的 ref 写死 `master`，
> 所以在哪个分支点都构建 master。

### 8.3 正式发版清单

1. `internal/app/app.go` bump `const Version`
2. `shell/android/app/build.gradle`：`versionName` 同步、`versionCode` +1（本次要出 APK 时）
3. **在 `RELEASES.md` 末尾追加** `# wild-work vX.Y.Z` 段落（新版本追加到末尾，旧的在上）
4. 本地 `go build ./... && go vet ./... && go test ./...` + `node scripts/ui-static-check.mjs`
5. 重建 `dist/wild-work.exe` 并用 §3 的 Python 计数核对版本号
6. 提交后打 tag：

```bash
git tag vX.Y.Z && git push origin vX.Y.Z
```

### 8.4 release note 从哪来

按优先级：

1. `RELEASE-<tag>.md`（历史遗留的独立文件形式）
2. `RELEASES.md` 里 `# wild-work <tag>` 起、到**下一个** `# wild-work ` 止的段落
3. 都没有 → `--generate-notes`（只有 commit 链接列表，对用户没有价值）

段落边界用"下一个 `# wild-work `"而不是版本号后缀比较，避免 `v2.6.3` 误匹配
`v2.6.30`。**段落缺失不阻塞发版**，但会静默退化成 commit 列表，所以务必先写段落再打 tag。

### 8.5 重发同一版本

```bash
gh release delete <tag> --yes --cleanup-tag   # 删 release + tag
git tag vX.Y.Z                                # 重打到新提交
git push origin vX.Y.Z
```

CI 的 `gh release create` 遇到已存在的 tag 会失败，**必须先删干净**。
